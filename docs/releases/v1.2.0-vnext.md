## Version semantics

The suite version uses simple SemVer-style semantics:

- **MAJOR** — breaking registry/installer contract changes, incompatible default behavior, or removal/renaming of maintained stable interfaces;
- **MINOR** — backward-compatible new skills, optional installer/evidence/validation capabilities, or maintained feature additions;
- **PATCH** — backward-compatible corrections, documentation/provenance fixes, test hardening, and implementation repairs.

A version-changing release is tagged `v<version>` only after the final release commit is on `main` and required CI is green.
