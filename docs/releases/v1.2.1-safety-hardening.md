# v1.2.1 — Installation Safety Hardening

Release date: 2026-10-01

v1.2.1 is a backward-compatible maintenance release focused on safer installation, stricter validation, CI trust, and future release maintainability.

## Installer safety

- resolves the default Codex skill target from the current OS user home instead of relying directly on a Windows-only environment variable;
- serializes mutating installs with an exclusive per-target sibling lock;
- keeps dry-run non-mutating and lock-free;
- rejects malformed or unclosed skill frontmatter before target mutation;
- requires matching skill names and description metadata;
- rejects referenced Markdown paths that escape the skill directory;
- rejects missing referenced Markdown files;
- warns when a no-selection full-registry install includes project-specific skills;
- recommends `-GenericOnly` or explicit `-SkillName` for normal reusable-skill installation.

The existing staged backup / swap / verify / rollback transaction is retained.

## Validator hardening

The root validator now also rejects:

- registry versions outside simple `X.Y.Z` SemVer form;
- evidence `skill_observations` that name unregistered skills;
- skill references that normalize outside their owning skill directory.

## CI hardening

- `actions/checkout` is pinned to immutable commit `3d3c42e5aac5ba805825da76410c181273ba90b1` (v7.0.1);
- the validation job has a 20-minute timeout;
- the CI self-contract rejects a return to a mutable checkout tag or removal of the timeout.

## Release maintainability

Historical v1.2.0 acceptance evidence remains immutable, but its contract no longer freezes the **current** registry version or README current-version string. A regression fixture proves a later suite version can coexist with valid v1.2.0 historical evidence.

## Evidence boundaries

This patch does not change the existing evidence limits:

- macOS repository-tooling execution remains NOT RUN;
- third-party runtime loading remains NOT RUN;
- runtime router obedience remains NOT RUN;
- incubating skills remain UNPROVEN unless their own post-creation evidence requirements are met;
- this maintenance release does not claim that skills cause better model output.
