# Provenance and public reuse

## Honest provenance

Distinguish between:
- direct copied material;
- adapted material;
- inspiration/benchmark references;
- official documentation;
- original synthesis.

Do not call a repository a fork if it is not a fork.
Do not claim "original" if substantial wording or structure was copied.

## Public release checklist

Before publishing:
1. choose a license;
2. verify attribution obligations;
3. remove secrets/private paths;
4. separate generic and project-specific rules;
5. add README/installation instructions;
6. add validation;
7. identify supported agent conventions;
8. state limitations.

## Attribution style

Good attribution says what a source informed.

Example:

```
@maintainer/project — informed retry/backoff and queue design patterns.
```

This is more useful than a generic "thanks to..." list.
